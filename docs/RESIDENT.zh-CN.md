# 人工智障修理厂：按需启动与自动反馈

技能版将桌宠与本地 Codex 聊天连接。安装一次后，需要时在 Codex 里说“启动人工智障修理厂”叫出来，不用时说“关闭人工智障修理厂”收起；不会随开机、登录或打开 Codex 自动出现。

## 安装与使用

将完整技能包中的 `qiaoqiao-feedback` 放入 `%USERPROFILE%\.codex\skills`，重启 Codex 后说“启动人工智障修理厂”。技能执行 `scripts/Start-Resident.ps1`：首次将完整运行包安装到当前用户 LocalAppData，后续复用；不要求每个聊天分别安装。

默认跟随你最近发过真人消息的本地 Codex 聊天。第一次命中锁定本轮目标；随后切换聊天不会把同一轮敲打拆送给别的聊天。连点、长按和甩鞭共用本轮资格，首次松手且约 2 秒安静后自动提交一条：

> 你这次做得不好，我很生气。请检查刚才的回答并纠正。

提示附带唯一反馈 ID 以识别本程序生成的消息。动画的自嘲台词不作为纠错消息发送。发送后，无论暂停多久、继续打多少下，都不再发第二条；只有按“重置”才开启下一轮。重置清除效果和计数，保留当前角色、工具和连接。它本身不发送；尚未提交的互动会取消，已入队的消息不会撤回。

## 实际聊天连接

常驻进程使用 Codex 公开的 App Server 聊天接口检查最近的真人输入，通过 `thread/queue/add` 排入一次反馈，与 `codex queue --thread <聊天ID> --message <提示>` 共用队列通道。不写私有聊天数据库、不注入键盘输入，不更改模型、推理强度或权限。

**已入队不等于 AI 已经回复。** 实测支持该接口的 Codex 版本能接收外部队列；已加载且空闲的聊天通常约 10 秒量级检测，正在工作的聊天在之后消费。关闭、未加载或中断的聊天可能要打开或恢复才能开始处理；当前实现不承诺立即唤醒任意未加载聊天。以界面状态、队列接收结果和目标聊天实际出现的回复分别验证。

最近活动只按真人消息排序。助手进度、后台任务、程序自身的自动反馈不改变目标；它不根据鼠标焦点猜聊天。连接失败应显示未连接或发送失败，不能仅凭本地生成了一条记录宣称已发送。

## 唤出与收起

需要时在 Codex 中说“启动人工智障修理厂”，或执行：

```powershell
./scripts/Start-Resident.ps1
```

运行文件位于 `%LOCALAPPDATA%\QiaoQiaoAI\resident\apps` 的版本目录。更新完整技能包后再次启动，脚本会识别包内较新版本，先请求当前进程正常退出，再安装到新的版本目录并启动，保留旧版本和反馈记录。更新或启动时会取消旧版留下且经核实属于本程序的登录启动项；不创建新的自启项，也不修改其他程序的启动项。退出请求失败时按返回信息关闭旧桌宠后重试。重复调用启动脚本不会新增一个实例。关闭桌宠退出当前运行，下次需要时再次叫出来；不会自动跟随 Codex 的打开或关闭。

检查状态：

```powershell
./scripts/Start-Resident.ps1 -StatusOnly
```

脚本返回最近写入时间和 `status.json` 内容，旧快照不证明进程还在。`launch_requested` 只代表启动请求，不表示 Codex 连接成功。

不用时在 Codex 中说“关闭人工智障修理厂”，或执行：

```powershell
./scripts/Stop-Resident.ps1
```

通过已安装程序的 `--resident-stop` 请求正常退出，不强杀其他进程。安装、版本、反馈记录和本轮反馈资格保留；请求失败时根据返回信息关闭仍在运行的桌宠。明确卸载时执行 `Uninstall-Resident.ps1`。安装/启动脚本可用 `-DataRoot` 做隔离测试，用 `-CodexPath` 指定兼容的 CLI；`-NoStartup` 仅保留旧命令兼容，当前默认就不自启。

## 一轮一次与数据范围

每次重置之间最多提交一次，停手不划分新轮。发送前持久消费本轮资格，未知结果不会自动重试。退出、崩溃或重新启动后仍保留已消费状态；只有按“重置”才开启下一轮并产生新 ID。旧 0.6.0 有发送尝试记录时，升级后保持锁定，先按重置再敲打。重置不会重放历史消息，也不能撤回已入队消息。网络结果不明时仍不承诺绝对“恰好一次”。

程序需要临时检查可访问的本地聊天元数据、轮次摘要及近期用户消息与时间戳，以确认最近真人输入、排除自动反馈。同轮较早真人消息被遮住时会有限向前查找，可能短暂经过其他消息或工具项，内容随读取丢弃；只持久化路由标识和聚合状态，不复制聊天正文，不作为额外内容提交。没有屏幕录制、键盘监听、账号凭证导出或逐次敲打 API 请求。约每 2 秒的本地接口检查不调用模型；实际反馈触发的回答仍消耗正常用量。
