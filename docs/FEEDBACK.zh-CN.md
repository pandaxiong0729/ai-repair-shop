# 人工智障修理厂：按需桌宠与自动反馈

技能负责安装、按需唤出和关闭桌宠。日常互动由桌宠自己连接 Codex：跟随最近发过真人消息的聊天，每次重置之间最多自动提交一条反馈，不需要手动点发送，也不需要让调用技能的聊天一直等待。

离线玩具版和 VPet 插件不连接聊天。产品名是“人工智障修理厂”；兼容入口仍是 `$qiaoqiao-feedback`，程序文件名仍为 `QiaoQiaoAI.Preview.exe`。

## 安装一次，日常直接敲

1. 按 [安装说明](INSTALL.zh-CN.md#技能版安装一次按需唤出) 放好完整技能包。
2. 在 Codex 中说：“启动人工智障修理厂”。
3. 桌宠底部显示“常驻 · 自动反馈”、目标聊天及连接状态。看到目标后即可敲打，不必填写原因。
4. 首次松手并停止互动约 2 秒，桌宠自动提交一次。之后继续敲打，哪怕停很久再打，也不会再发。按“重置”后才开启下一轮，无需重新调用技能。

桌宠只在你要求时出现，不随 Windows 登录、开机或打开 Codex 自动启动；不用时说“关闭人工智障修理厂”，下次需要时再叫出来。重复调用技能复用安装和同一个实例。更新或启动时会取消本程序的旧登录启动项。透明桌宠可以通过专用拖动手柄移动，拖动手柄不产生反馈；完整参数见 [按需启动说明](RESIDENT.zh-CN.md)。

## 多窗口与一轮的边界

- 目标由**真人最近发消息的时间**决定，不按当前鼠标焦点或助手最后更新排序。程序自己的自动反馈不参与排序。
- 第一次实际命中锁定本轮目标。发送前按该次命中的时间重新核对，即使中途向另一个聊天发消息，也不会把正在进行的这一轮改送过去。
- **“重置”是轮次分界，停手不是。** 连点、长按、喷射和拖鞭共用本轮资格；首次松手并安静约 2 秒后封存一次。此后暂停、继续敲打、切工具、换角色或换聊天都不产生第二条，玩法动画仍可继续。
- 如果首次命中时尚未连接或无法确认目标，本轮不会在后来连接成功时悄悄补发给别的聊天。恢复连接后先按“重置”，再敲打开始新轮。
- “重置”清除效果和可见计数，保留角色、工具与连接，并开启下一轮反馈资格；它不是发送按钮。重置前还没提交的草稿会丢弃；已经入队或发出的反馈不会因重置撤回。
- 本轮发送资格持久保存，退出、崩溃、重启或重新调用技能都不会代替重置。旧 0.6.0 有过发送尝试时，升级后先保持锁定，按“重置”再开始。

目标显示用于确认当前路由。程序不把桌面窗口的排列、切换或焦点当作已发送消息的证据。

## 真实连接如何工作

```text
常驻进程 → 公开 App Server 查询聊天摘要和近期用户消息 → 确认最近真人输入
重置 → 开启本轮资格 → 第一次命中固定时间与目标 → 首次停手约 2 秒
持久消费本轮资格 → thread/queue/add 提交一次 → Codex 桌面端消费队列
继续敲打 / 暂停 / 重启 → 保持已反馈，不再发送 → 按重置才开启下一轮
```

`thread/queue/add` 与公开命令 `codex queue --thread <聊天ID> --message <提示>` 使用同一条队列通道。程序不通过 `turn/start` 另起一个替代聊天，不模拟键盘发送，也不写私有聊天数据库。它沿用本机已登录的 Codex，不要求额外 API Key，不改目标聊天的模型、推理强度或权限。

本轮提示形如：

```text
[人工智障修理厂反馈:<本轮唯一ID>] 你这次做得不好，我很生气。请检查刚才的回答并纠正。
```

不把动画中的夸张自嘲台词、逐次敲打记录或其他聊天的内容附加到这条提示里。桌宠表达的是用户不满；AI 仍需结合目标聊天的上下文找出问题，无法仅凭敲打次数知道具体哪里错了。

## “已提交”与“聊天已收到”不同

| 状态 | 含义 |
| --- | --- |
| 已连接、显示目标 | 连接可用，能够确认最近真人消息；尚不代表本轮已发送。 |
| 本次若干下、等待停手 | 本轮仍在本地聚合，尚未提交。 |
| 已自动提交 1 条、等待 Codex 处理 | 队列接口已经接受；不能据此声称 AI 已回复或已纠正。 |
| 聊天已收到 1 条反馈 | 目标聊天中已能确认这条反馈 ID；仍应以实际回答判断是否完成纠正。 |
| 本轮已反馈／等待重置 | 本轮资格已用，继续敲打只播放动画；按“重置”才允许下一条。 |
| 本次未发送／结果不确定 | 未连接、目标无法确认、请求被拒绝，或发送结果未知；不会把本地记录当作送达，也不会自动重试。恢复后按“重置”再开始新轮。 |

已加载且空闲的 Codex 桌面聊天通常约 10 秒检测外部队列。正在工作的聊天在之后的正常空闲阶段处理；关闭、未加载或中断的聊天可能需要打开或恢复。公开队列已在现有体验聊天中确认被消费并产生回复，其中后一次无需额外切换到目标聊天；这不等于任何未加载聊天都能立即唤醒。具体版本和完整验证范围以 [验证记录](VALIDATION.md) 为准。

常驻进程约每 2 秒检查本地接口，不需要模型维持轮询回合；这部分不产生模型推理 token。实际反馈进入聊天并触发回答时仍消耗正常用量。多次敲打汇总成一条提示，不能承诺 AI 后续纠错只用固定数量的 token。

## 怎么测试

1. 保持桌宠运行，先按“重置”。在聊天 A 发送一个简单请求并等它回答，确认桌宠显示 A。
2. 在聊天 B 发送一个请求，确认目标切到 B。只切窗口而不发消息，不应改变目标。
3. 在 B 最近发过消息后，连续敲打、长按或甩鞭几秒，松手。无需点任何发送按钮；停手后应显示只提交了 1 条。
4. 等 B 处理队列，确认其中出现一条固定纠错提示并作出回应。助手在 A 产生后台进度不应改变目标。
5. **不按重置**，等十几秒后再连击或甩鞭，聊天中应仍只有原来 1 条反馈；换工具、换角色后继续打也不能新增。
6. 点击“重置”本身不应新增消息。重置后再敲打并停手，才允许第 2 条反馈。
7. 发出一条后关闭并重开桌宠，不按重置继续打，应仍不新增。若在首次自动提交前按重置，待发互动应取消，重置本身不发送。
8. 测试跨窗口时，先重置，在 B 最近发过消息后开始敲打，再向 A 发消息；该轮仍送给开始时的 B。按重置开启下一轮后，才跟随 A。

若已显示队列接受但暂时没有回复，先查看目标聊天是否已加载、忙碌或中断。未加载时打开它，正在运行时等其正常处理。若程序提示连接失败，可查看安装脚本的 `-StatusOnly` 输出及本地错误状态；不要反复重放同一轮制造重复提示。

## 读取与保存的数据

程序通过公开接口获取本地聊天元数据、近期轮次摘要，以及用于判断真人输入的用户消息项和时间戳。若同一轮中的新消息遮住了此前的真人输入，会有限向前查找；该路径可能短暂经过其他消息或工具项，内容随读取丢弃，不持久化成聊天副本，也不附加发送。

本地保存路由标识、聊天标题、真人消息 ID/时间、本轮 ID、工具/角色聚合次数和投递状态。默认目录是 `%LOCALAPPDATA%\QiaoQiaoAI\resident`；`status.json` 是状态快照，`rounds` 保存去重与投递记录，另保存本轮是否已消费的持久状态。没有屏幕录制、键盘监听、账号凭证导出或私有数据库读取。单纯玩具模式不进行这些聊天检查。

## 重复与异常处理

本轮在外部提交前先写入发送中状态。服务器确认后记为队列接受；明确拒绝记为失败；超时、断连或进程在发送中退出留下未知结果。未知结果不自动重试，以免对同一聊天重复施加提示。不要删除去重记录来强行重放。

这种设计避免程序自动重复提交，不保证网络端绝对“恰好一次”。只有显式按“重置”才开启新的发送资格；恢复连接或停手后再打不会自动开新轮。关闭桌宠不会撤回已进入 Codex 队列的消息。

## 旧版 v0.5.3 兼容

旧 `Start-Feedback.ps1` / `Read-Feedback.ps1` 及原会话目录保留，供已打开的旧窗口或兼容测试使用。旧版需要手动发送并由调用聊天读取本地文件，不能自动唤醒聊天；它不再是默认技能流程。旧协议详见技能目录下的 `references/protocol.md`。升级后若仍看见“发送本轮反馈”，那是旧窗口或旧运行文件，请使用 0.6.1 的常驻入口。
